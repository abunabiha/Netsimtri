## 3. Langkah kerja

### 3.1 Siapkan repositori

```bash
# buat folder dan inisialisasi
mkdir netsimtri && cd netsimtri
git init
echo "22" > .nvmrc

# buat struktur folder
mkdir -p .github/workflows docs/lampiran docs/adr docs/milestones
mkdir -p engine/src engine/test cli/ios15 cli/iosxe server web data
```

### 3.2 Salin dokumen perencanaan

- Salin PRD ke `docs/PRD.md`.
- Salin Lampiran A, B v2, C, D ke `docs/lampiran/`.
- Salin panduan development ke `docs/`.

Agen Antigravity perlu membaca dokumen ini sebelum menulis kode.

### 3.3 Inisialisasi package

```bash
npm init -y
npm install --save-dev typescript vitest @types/node
npx tsc --init
```

### 3.4 Buat kerangka aplikasi minimal

Cukup server yang menyajikan halaman kosong dan endpoint `/health`. Tujuannya memastikan rantai build dan Docker bekerja, bukan fitur.

Minta agen membuat:
- `server/index.ts`: server HTTP yang melayani `/health` (mengembalikan 200) dan halaman placeholder.
- `engine/src/index.ts`: berkas kosong dengan satu fungsi contoh dan satu tes, untuk memverifikasi pipeline tes.

### 3.5 Pemetaan CCNA v1.1 ke data

Buat `data/blueprint-ccna-200-301-v1.1.json`. Isinya daftar domain dan objektif dari Lampiran A. Contoh bentuk:

```json
{
  "exam": "ccna-200-301-v1.1",
  "validUntil": "2027-02-02",
  "domains": [
    {
      "id": "1.0",
      "name": "Network Fundamentals",
      "weight": 20,
      "objectives": []
    }
  ]
}
```

Isi `objectives` diisi dari PDF resmi jika sudah tersedia. Jika belum, tandai setiap domain dengan `"source": "secondary"`.

### 3.6 Tulis ADR pertama

Buat `docs/adr/0001-simulasi-di-server.md`:

```
# ADR 0001: Menjalankan simulasi di sisi server

## Konteks
Simulasi bisa berjalan di browser atau di server. PRD menargetkan
konsistensi antar-browser dan kontrol dosen atas skenario.

## Keputusan
Mesin simulasi berjalan di proses Node.js di dalam container.
Browser hanya menampilkan GUI dan mengirim perintah lewat API.

## Konsekuensi
- Positif: hasil konsisten, bisa diuji tanpa browser, dosen bisa
  mengontrol skenario.
- Negatif: beban server naik saat banyak siswa aktif. Perlu diukur
  (risiko di PRD bagian 13).
```

### 3.7 Dockerfile dan compose

Pakai kerangka dari panduan bagian 7. Pastikan:
- Build lolos tanpa error.
- Container berjalan non-root.
- Endpoint `/health` merespons.

### 3.8 Aktifkan CI

- Tambahkan `ci.yml` ke `.github/workflows/`.
- Push ke GitHub.
- Pastikan Actions berjalan dan hijau.
